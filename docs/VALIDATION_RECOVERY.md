# 模型字段校验与增量恢复（2026-10-31）

## 原因与处理

真实任务 `0de4b927-d03c-4704-a180-49b42f6ace01` 的历史异常为 `ResearchBatch.intents` 和 `OpinionAuditBatch.content_class` 的 `literal_error`，表示模型返回值不属于协议枚举。API 已正常返回内容，不是登录或鉴权失败。历史日志未保存非法字段原值，无法追溯具体写了哪个值；不据此猜测。

原实现已隔离失败记录、保留合格记录，但修复请求没有带回前次 JSON，字段错误提示也未明确枚举允许值；批次请求耗尽重试后，没有逐条独立恢复步骤。失败记录需要通过通用重新分析入口处理，缺少明确的只修复失败项入口。

现在的行为：

- 字段错误列出路径、类型和枚举允许值，不写入输入正文、密钥或模型完整响应。
- 请求内的修复上下文包含前次 JSON，仍发送至用户已配置的同一模型服务；不持久化完整响应。
- 保留同批合格记录，对失败的研究标注/观点复核单独恢复一次；每次底层请求仍最多两次。没有递归重试。
- 未通过的枚举不被猜测转换为合法值；缺失/重复 ID、观点序号、原文片段和证据约束仍然检查。
- 传输、鉴权、余额等失败停止任务；先保存同批合格记录，不会将调用失败伪装成可恢复的字段错误。
- 已恢复的临时字段错误保留于事件历史，不继续作为当前报告警告。
- 程序拦截与模型证据复核拦截的生成表述统一去重计数，修复此前警告仅计前者的漏算。

## 使用入口

工作台“分析校验详情”展示评论校验待复核、未归类观点、生成表述待复核，三者采用不同单位，不合并加总。

有可修复评论时，点击“修复校验失败项”。对应 `POST /api/tasks/{id}/analysis/repair`，在后台执行：

1. 只对失败的原始观点复核进行提取/复核恢复（初提取有效则复用）。
2. 只更新选中评论的独立研究标注，保留其余成功分析和人工修正。
3. 复用未变观点的主题映射，只为新增/变化观点归类，按实际有效数据更新报告。

仅适用于已有 V3 AI 决策报告、当前空闲且存在可修复评论的任务。不重新采集。没有可修复记录时返回 409；主题未分类和证据不足的生成表述不会被这一步强行放行。
