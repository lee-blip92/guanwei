# 多平台采集、登录与恢复

## 平台选择与真实能力

首页选择“多平台采集”，勾选需要的平台，可单选、任意多选或全选。默认仅小红书；一个任务分析一个软件/互联网产品。平台按选择顺序串行执行，不同时启动多个采集浏览器。

| 平台 | 标识 | 当前适配搜索排序 | 内容与评论 |
| --- | --- | --- | --- |
| 小红书 | xhs | 综合、热门、最新 | 笔记、一级评论、可获取回复 |
| 抖音 | dy | 综合、热门、最新 | 视频、一级评论、可获取回复 |
| 快手 | ks | 平台默认 | 视频、一级评论、可获取回复 |
| B站 | bili | 综合、播放量、最新 | 视频、一级评论、可获取回复；不采弹幕 |
| 微博 | wb | 综合、热门、实时 | 微博、一级评论、接口返回的嵌入回复；无完整回复分页 |
| 贴吧 | tieba | 相关性、最新 | 帖子、楼层评论、可获取楼中楼回复 |
| 知乎 | zhihu | 平台默认 | 回答/文章/视频、一级评论、可获取回复 |

仅显示所有已选平台共同支持的排序；改变选择后，不再支持的排序自动回到默认。“热门”并非统一指标，例如 B站按播放量。没有统一日期范围过滤，不保证评论完整。

## 本机准备与开始

1. 保留 `md` 及其许可证，确认 `md/.venv/Scripts/python.exe` 和 Chrome 可用。无须打开 MediaCrawler 的 8080 WebUI。
2. `.env` 设置 `MEDIACRAWLER_PATH=./md`；使用其他环境时设置 `MEDIACRAWLER_PYTHON`。模型密钥只由应用后端读取，不传给采集子进程。
3. 启动观微，输入产品、选择平台，检查可编辑搜索词与高级设置，然后开始。
4. 任务详情显示实际总数和各平台状态、内容数、评论数、失败数。评论按平台筛选，报告与导出保留来源和平台分布。

不要同时运行共享相同 MediaCrawler 专用 profile 的外部采集程序。应用内锁不能锁住外部程序。既有 profile 存在不表示登录有效。本应用未编辑上游源码、配置文件或既有登录文件；真实运行时，MediaCrawler 按其配置管理专用浏览器 profile。

## 数量预算

上限按**每个平台**分别计算：默认每个平台 5 条内容，每条内容最多 20 条一级评论，含回复最多 100 条评论。选两个平台合计最多 10 条内容、200 条评论。回复消耗该平台总预算；不会为凑数量提高上限。

关键词使用有限预算轮询，非随机抽样。平台可能少于上限返回。跨平台账号不合并身份；评论数不等于独立用户数。

## 登录、验证与故障

每个平台独立子进程，浏览器 profile 由上游按平台隔离。未登录/失效/验证时，当前平台进入“等待登录”，后续平台等待：

1. 用户亲自在 MediaCrawler 打开的独立 Chrome 完成登录或平台验证。
2. 回到观微点击“我已完成登录，恢复采集”。只恢复当前平台。
3. 适配器刷新 cookies；仍未通过时继续等待，不伪装成功。

不解验证码、不替用户输入 OTP。未知总量不显示百分比。普通请求失败保留已采数据；平台失败后继续后续平台。已有评论时生成“部分完成”报告，没有任何评论则明确失败。

取消会停止当前平台并取消剩余平台，保留已存数据。零评论、失败与未执行均有实际状态，不伪造样本。

## 恢复与重新分析

- 活着的子进程登录暂停后可在原请求边界继续。
- 重启把遗留任务标记失败、未结束平台标记中断，不自动重复采集。
- “恢复采集”重新搜索所选平台，按平台与评论 ID 合并；已有内容/评论计入相应上限。**不是断点游标恢复**，不保证补齐已处理内容遗漏的回复。
- “重新分析”只读已保存数据与人工修正，不打开浏览器。

## 多平台导入

支持 JSON、JSONL、MediaCrawler Excel。单平台任务可省略平台；多平台任务必须标记记录 `platform`，或在 JSON 顶层指定默认值。首页和详情提供“文件默认平台”，可依次导入各平台原生 Excel/JSON。该选项仅补全未标记的记录，文件明确平台优先。

```json
{"platform":"dy","notes":[{"aweme_id":"真实视频ID","title":"真实标题"}],"comments":[{"comment_id":"真实评论ID","aweme_id":"真实视频ID","content":"真实原文"}]}
```

上传 API 可用 `X-Platform: dy` 指定文件默认平台。禁止未选平台进入任务，不根据数字 ID 或文本猜平台。混合 JSONL 的内容行使用 `kind: note`。原生字段转换为统一契约；原文件和原对象均保留，缺失字段为空。

## 接口与存储边界

能力注册表 `platforms.py`；编排 `crawler.py`；小红书 `crawler_bridge.py`；另外六平台启动 `multi_bridge.py`；有界搜索/分页 `upstream_adapter.py`，均在 `backend/insight`。覆写上游默认搜索循环，避免自动把小上限提高至 10/20。

子进程仅发 `INSIGHT_EVENT <json>`：collecting、waiting_login、note、comments、failure、fatal、done。不转发上游普通日志。任务配置和控制标记在 `runtime/tasks/<id>/<platform>/`，导入文件在 `<id>/imports/`。

内容按任务＋平台＋内容 ID 隔离，评论和父关系按平台＋评论 ID 隔离；知乎内容 ID 加类型前缀，避免文章与回答同号混淆。前端不依赖上游数据类。升级 MediaCrawler 后须重新跑协议测试和人工登录小规模检查。
