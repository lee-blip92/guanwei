# DeepSeek 真实 API 重新验收

日期：2026-10-30（Asia/Shanghai）。模型：`deepseek-v4-pro`；官方接口：`https://api.deepseek.com`。

## 验收结论与边界

已跑通：已有真实小红书 Excel 导入 → DeepSeek 分批提取 → 主题归并 → 报告生成与证据支持自检 → 网站展开原文 → Markdown/CSV/打印 HTML/JSON 导出。

程序约束与界面链路已通过；没有人工金标准，不能据此声称筛选/主题准确率。模型证据自检仍可能误判，真实报告需研究者核查。没有重新执行小红书采集、平台登录或浏览器另存 PDF。

## 修复的问题

1. **配置未生效**：真实配置写在 `.env.example`，后端只加载 `.env`。已迁移到 `.env` 并清空示例中的密钥；`.env` 继续忽略于 Git。检查了 86 个相关文本文件，未发现实际密钥出现在源码、文档或导出中。
2. **DeepSeek 默认思考模式延迟**：官方接口默认高强度思考，首批十条约一分钟。现对官方主机明确使用非思考模式，保持 `deepseek-v4-pro`；可用 `DEEPSEEK_THINKING_MODE=enabled` 恢复。参数只发送到精确匹配的官方主机，不影响其他兼容服务。
3. **逐字引用被近义改写**：真实批次中把“原来”改为“看来”，原校验正确拦截。已明确短连续引用并增加一次契约级重试；仍不合格就失败，不更改原始评论。失败批次重现后通过，完整复跑全部 381 条通过。
4. **ID 存在但语义不支持**：全主题场景与少量代表原文混用，导致部分细节引用错配。报告输入已收紧为所选原文，不传入其他评论的场景推断；核心部分最多八主题，候选结论逐条做证据支持自检，不支持或不确定的候选项剔除。完整长尾主题与证据仍保留。
