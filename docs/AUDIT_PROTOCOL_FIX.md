# 飞书多平台任务：观点复核序号失败修复

日期：2026-10-30。任务 `27587ab4-ab78-48af-8a42-7e8c41c04feb`。

## 观察到的原因与边界

小红书、抖音均采集完成，各保存100条评论；已有100条完成观点分析，另10条初提取已缓存、90条尚未处理。接下来一批10条包含8条零候选观点、2条单候选观点。复核输出在一次有界重试后仍未覆盖预期观点序号，导致原实现整批失败。历史记录只保留通用校验错误，没有存储具体错误返回，不能断言是哪一条漏项、重复或从1开始编号。

这次最新失败是输出契约错误。该任务较早的历史运行也曾收到 HTTP 402，但最近两次停止原因均为观点序号校验，并非最近请求返回402。原始200条评论、100条已完成分析和10条初提取均保留。

## 修复

- 在候选观点上显式发送 `point_index`，每条评论附 `expected_point_indices`。空候选明确要求空checks，复核不得新增观点。
- 错误记录包括评论ID、预期序号及实际序号；不记录密钥或模型原始响应正文。
- 有界重试后仍不符合契约时，逐条隔离；只保留完整匹配、原文校验通过的评论。问题项标记 `opinion_audit.state=needs_review`、待确认、无有效反馈，不支撑报告；后续批次继续。
- 报告显示待核查数量，并标“部分完成”；不把协议失败伪装成通过复核。人工逐观点修正可覆盖；再次分析只重试尚未通过的复核，初提取继续复用。
- 这是协议强化，未改变观点语义判据；保留既有成功复核的指纹，避免为了本次修复重复调用已完成100条的模型复核。
- 页面把“失败0次”明确为“采集失败0次”，避免与模型阶段错误混淆。模型HTTP/连接/结构解析错误仍停止并保留数据。

本轮没有为该任务发起新模型请求、重新采集或改写分析标签。修复上线后，用户可点击“重新分析”继续：复用100条完整结果和10条初提取，再处理未完成数据。模型费用和当前账户状态由提供商实际响应决定，未重新测试余额。

测试覆盖漏项、重复、从1开始、空候选新增观点、未知评论ID、无效父引用，以及首批复核不合格后后续批次继续；模型均为协议替身，不是新增真实API调用或质量评估。

实际结果：全套 **105 passed（29.65秒）**，TypeScript与Vite生产构建通过。记录见 `examples/acceptance/audit-protocol-fix-tests.txt`、`audit-protocol-fix-build.txt`。已在没有活动任务时重启本机服务加载修复；原失败任务保持原状态，未擅自重跑模型。
