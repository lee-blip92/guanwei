# 决策洞察 V3 Implementation Plan

**Goal:** 用层级产品维度、独立分析轴和可核对统计，生成精简决策报告与完整证据附录。

**Architecture:** 保留V2原始观点及成功缓存；新增评论研究标注与阶段缓存、产品动态分类、确定性统计与优先级、证据约束洞察。继续单进程FastAPI/SQLite后台任务与React，不引入向量数据库或队列。新任务默认决策报告，旧报告可按需升级，升级复用已采集及原始观点，不重复采集。

**Tech Stack:** Python/Pydantic/httpx、SQLite、React/TypeScript、HTML/CSS图表、Markdown/CSV/打印HTML。

## 决策

- 不只做报告改写，也不替换成固定行业模板；采用受当前产品样本约束的一级维度（最多8个）＋二级核心议题（初始最多32个，允许有依据新增，超出范围待归类）。保留原始aspect/topic/quote。
- 研究标注独立包括意图、评价对象、情感、立场、体验/猜测证据类型、明确后果/场景；教程/第三方评价、猜测不作为产品体验或已发生痛点。需求不等于满意。
- 身份去重仍为平台+评论ID。用户ID只取上游实际字段，跨平台不合并；讨论串沿真实父关系解析，缺失/环路不猜根。附和与直接详细描述分列；同文不同ID保留并提示。
- 所有数量/分母/图表/优先级由程序计算，评论覆盖按唯一ID；可识别用户、可解析串仅为已知下界，不是独立故障人数。统计口径单独登记。
- P0仅为明确严重风险线索的优先核查；P1/P2/P3按独立串、直接反馈、明确任务影响与证据缺口分层。业务价值、开发成本默认未知；不据评论指定开发排期。
- 优先级卡片保留事实原话、归纳、待验证原因、建议方向、验证方法和指标；前5条进入摘要，主文Top6，其余附录。相反意见分开展示。
- 空缺信息允许未知；模型输出结构或语义问题按项隔离，不能将未经检查内容计入报告。旧的完整报告在升级前保存快照。

## 实施

1. **来源与状态**：保留/回填真实user_id与父关系已知标记；新增research_cache；纯函数负责研究标注有效性与effective标签，保证工作台/CSV/报告同源。
2. **独立研究轴**：分批审阅既有观点，结构化输出与当前/父字面引用校验，按评论缓存；人工修正优先，原始细粒度结果可核查。
3. **层级与归并**：产品专属动态分类，复用已有类；分批映射、同义去重、未知项待核查；保持分歧和不同问题表现。
4. **统计与质量**：评论/观点/串/用户/附和口径；原因汇总；证据依赖、百分比分母、对象与意图错配、重复分类、影响引用等可复现检查。
5. **决策与报告**：可解释研究优先级、核心发现/优势/机会/验证指标；精简/完整模式，前端可视化和三种导出同源，完整证据仅在附录展开。
6. **验证**：真实飞书200条升级一次；检查与升级前差异，报告/CSV/页面/导出数量一致；多个不同产品的构造用例验证动态类别、缺ID/用户/父关系、争议、单评多观点、严重低频风险、人工排除。实际效果指标仍需独立人工标注，不编造准确率。

文件预计：`decision_state.py`、`decision_analysis.py`、`decision_exports.py`、`DecisionReport.tsx`；修改schemas/db/ingest/platforms/jobs/app/exports/App/OpinionEditor/types；新增`tests/test_decision_insights.py`与只读验收脚本。根目录无Git仓库，沿用当前checkout；独立执行，不启动子Agent。
