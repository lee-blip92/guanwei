# 产品用户反馈洞察工具 Implementation Plan

**Goal:** 在本机跑通小红书真实数据导入或采集、中文反馈分析、人工核查、带证据报告和导出。

**Architecture:** React 工作台调用独立 FastAPI 服务。SQLite 持久化任务、原始记录、规范化评论、人工修正和报告。单进程后台调度，独立子进程适配 MediaCrawler；分析通过可替换的 OpenAI-compatible 客户端分阶段执行。

**Tech Stack:** React / TypeScript / Vite；Python 3.11 / FastAPI / SQLite / httpx / Pydantic。

## 设计选择

- 采用轻量后台调度，避免为单机单用户引入队列基础设施。任务有持久状态，重启会终结遗留运行任务并允许手工复用数据重试。
- 采用小批量 LLM 提取与层级主题归并，暂不引入向量聚类。中文场景避免照搬 Sift 默认英文模型，也避免小样本强行聚类。
- 无密钥时提供明确标识的本地规则预览。模型错误不会静默切换为规则或伪造成功。
- 界面采用冷灰底、深蓝文字与青绿色重点的研究工作台；表格核查、上下文抽屉和报告证据关联是主要交互。

## 实施顺序与验收

1. 审计上游 README、接口、数据结构、许可证，记录版本和复用边界到 `docs/UPSTREAM_AUDIT.md`。
2. `backend/insight/` 实现 schema、SQLite、JSON/JSONL/Excel 规范化、ID 去重和不可变原始记录。测试同 URL 不同评论、缺失 ID、父评论补全。
3. 实现分批结构化提取、主题归并、报告与证据校验。测试短评、对比产品、人工排除、非法证据、模型失败。
4. 实现后台任务、采集子进程事件协议、登录暂停/恢复、取消和重启恢复。测试等待登录与部分失败。
5. 实现任务首页、评论工作台、报告、设置及 Markdown/CSV/打印 HTML 导出。构建 TypeScript 并浏览器核查。
6. 用本机已有 Excel 跑真实数据导入；生成明确来源的报告。演示样本独立标记；不声称执行了未经验证的真实采集或模型调用。
7. 提供启动脚本、环境变量、架构/数据库/提示词文档、评估方案与测试记录，清理临时产物。
