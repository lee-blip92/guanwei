本轮改分析链路，保留现有网页、图表、精简/完整报告与共享打印模板。使用已有真实任务 `0de4b927-d03c-4704-a180-49b42f6ace01`，小红书500条、抖音500条、51条来源内容，调用用户已配置的 `deepseek-flash`。没有重新采集，也没有以演示数据代替。

## 根因及实际修复

| 根因 | 修改及边界 |
| --- | --- |
| 二级类别直接作为核心问题，同模块被当作同问题 | `semantic_quality.py` 按对象/任务/障碍建议题，允许具体长尾；全局同义归并后独立审核每条成员，再核对多成员议题整体共同边界。不同问题拆开，标题只保留实际共同范围。 |
| 同类别正负即体验分化 | 单独审核正反pair，仅展示对象和任务可比的已通过pair；不同功能的正负意见不构成分歧。最多2×2代表pair，不能据此断言没有其他分歧。 |
| 场景来自全类别，生成只引用少量代表 | 事实字段与实际允许证据集合统一；代表3条只用于阅读。摘要沿用观察实际引用，不换成代表评论。 |
| 结论核验只验证ID、批量语义检查仍会串用内容 | 原文、ID、归属由程序检查；逐条独立语义核验同时检查议题范围。叙述不发送笔记正文；生成、核验、改写仅对附和使用可用父评论，不能把直接反馈的父评论当本人经历。 |
| 字段复制和严重后果外推 | 分角色保存连续原文，重复或非原文置空；没有明确后果则未知，疑问/猜测不升级为事故。原始观点保留。 |
| 单条潜在风险直接P0、共性反馈排后 | 四因素研究优先级；单条严重风险为P1并标低证据待验证，共性跨串问题也可P1；摘要分别选共性/严重风险/优势，开发优先级未知。 |
| 固定类别上限与整批失败丢弃可用项 | 注册新具体议题；归并ID遗漏/重复有界修复一次，冲突项保留原分类并提示复核，合格候选也须逐条审核。失败表述改写后重新核验，仍失败不进正文。 |

结构定义在 `semantic_schemas.py`，提示词和阶段边界见 [AI设计](AI_DESIGN.md)。派生数据仍存现有SQLite阶段缓存，旧协议/旧报告和人工修正兼容；不引入向量库、队列或新服务。`decision_trace` 与证据抽屉可反查本评论支撑的议题与表述。

归并调试发现248个初始细粒度定义的全局返回有ID遗漏/重复；修复后仍冲突的项保留原分类，不伪造完整成功。最终多成员边界检查覆盖38个议题：24组共同范围通过、10组拆分、4组边界不明保守拆分，审核理由保留。300条成员初审中179条通过、105条拆分、8条改回整体态度、8条待确认。其余分配不完整观点保留未映射。

优先准确性后，仍保留大量单条长尾：最终11个一级维度、221个二级明细，其中194个仅覆盖一条评论。正文只呈现核心议题，完整明细在附录；本轮没有宣称标签粒度已经最佳，也没有为减少数量把不同问题重新合并。这些长尾和被拆分的同义边界是后续人工抽检重点。

实际正文核查曾发现“卡顿”观察扩展了引用中没有的“打开页面”场景；补修后叙述移除笔记正文、核验隔离到每条结论。附和评论仍可合法引用父评论明确描述的“发图片”表现，该上下文不计作新的独立故障人数。严重风险单条内容覆盖/恢复反馈维持P1核查，而非P0开发结论。

## 仍需人工确认

- 18条观点的具体对象/任务或原文依据不明，另有11条可用观点没有可靠议题，共29条观点待复核；不强制归类以凑覆盖率。
- 归并ID冲突、整体边界不明以及长尾是否同义仍保留复核理由。模型审核可能误判，不因“通过”就视为人工确认。
- 连续原文/精确重复由程序可复现校验；语义重复、具体场景和因果仍需人工抽查。P1仅表示核查顺序，不是开发排期。
- 固定真实样本10条尚未人工标注，`human_metrics=null`。没有真实分类准确率、Precision/Recall/F1或节省时间数据。人工标注结构和抽样方案见 [评估方案](EVALUATION.md)。
