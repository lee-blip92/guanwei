# 产品需求与作品集说明

## 问题与最小目标

目标用户：产品经理、独立开发者、产品研究人员。当前痛点不是单纯缺少“总结”，而是社交内容分散、评论依赖上下文、对比产品容易归错、结论无法回到原文核查。

MVP 的完成条件是一位研究者能在本机给一个软件产品创建研究任务，从七个平台中选择一个或多个，用真实导出数据或小规模采集形成可核查报告，修正判断后重新生成，并导出评论明细与报告。产品不承诺代表全部用户，也不制造画像、商业损失或精确置信度。

## 核心用户流程

1. **定义对象**：产品名称；可能重名时补简介/官网；可选关注问题与别名。
2. **检查样本入口**：生成并编辑中性/正面/问题搜索词；选择平台及导入/真实采集；明确每个平台的小规模上限。
3. **等待并处理异常**：后台执行，刷新保留状态；未知总量显示实际数量；登录验证暂停；错误提示可恢复操作。
4. **核查判断**：搜索与筛选评论，查看笔记、父评论和原文；编辑标签、排除或恢复；记录理由。
5. **读报告**：查看样本范围、主题与发现；展开证据核查；区分观察、直接表达、建议、待验证问题。
6. **迭代与导出**：复用数据重新分析，输出 Markdown、CSV、打印 HTML。

## 信息架构

- 任务首页：主要输入、可展开设置、来源与模式选择、历史任务；无任务时有明确空状态。
- 评论工作台：当前阶段与真实计数、评论表格、筛选、证据核查抽屉、人工修正、重新分析/取消、执行事件。
- 洞察报告：范围、统计、发现、主题、情绪、正面体验、建议、待验证问题、限制与导出；每项可回到评论。
- 设置：非敏感模型配置与连接测试；后端密钥配置说明；采集可用性、登录状态未知说明和许可来源。

页面采用“观微”中文研究工作台：冷灰留白、青绿强调、表格阅读、原文抽屉与克制的报告版式。桌面为主，窄屏通过侧栏压缩、表格横向滚动与面板重排保证可用。当前构建已验证，已使用内置浏览器核查多选与来源展示，截图见多平台验收记录。

## 决策与取舍

| 决策 | 原因 |
| --- | --- |
| 先支持真实数据导入 | 平台登录/网络不是分析开发的前置，能独立验证完整链路 |
| 多平台串行执行 | 避免共享浏览器与全局配置冲突；一个平台失败保留样本并继续其余平台 |
| 单进程后台与 SQLite | 单机单用户足够，降低部署门槛 |
| 采集模块独立可替换 | 上游接口可能变化，并存在商业许可限制 |
| 显式规则预览 | 无密钥也能核查数据流程；不冒充模型语义结果 |
| 不引入向量聚类 | 中文默认模型与小样本噪声需要额外验证，当前分阶段语义归并更直接 |
| 待确认单独保留 | 归属不足的内容不应被强行丢弃或算作目标反馈 |
| 人工修改使旧报告失效 | 防止报告继续引用已排除数据 |
| 不推断业务优先级 | 评论样本无法支持损失、成本和全体用户结论 |

## 异常体验

空数据等待导入；后台有阶段与真实计数；零有效反馈报告明确无可支持结论；部分采集失败保留可用结果并标部分完成；登录失效暂停与恢复；模型失败保留数据且不静默降级；应用重启终结遗留执行态；数据格式错误事务回滚并指明原因。

## 如何放入求职作品集

可以展示：需求与非目标、上游真实能力审计、模块边界、中文短回复与产品归属问题、提示词/JSON schema、人工反馈闭环、可追溯报告、状态机与测试结果。

2026-10-29 的首次真实导入报告展示的是数据工程和核查闭环，当时用户选择先完成规则预览。后续模型与浏览器验收应按日期记录在测试文档，不能将调用成功等同于质量评估。人工标注与平台新采集仍需独立验证；不要编造“准确率 95%”“节省 80% 时间”等指标。
